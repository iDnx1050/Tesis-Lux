2. Hallazgos Detallados y Correcciones

H-01 · A05:2025 — Security Misconfiguration · ALTA

Ausencia de cabeceras de seguridad HTTP

Descripción: El archivo next.config.mjs no configuraba ninguna cabecera de seguridad HTTP. Cualquier respuesta del servidor carecía de protecciones estándar contra clickjacking, sniffing de contenido, inyección de frames y otros vectores de ataque pasivos.

Impacto:

  • Sin X-Frame-Options: el sitio podía ser incrustado en iframes de terceros (clickjacking).
  • Sin X-Content-Type-Options: navegadores podían interpretar respuestas con MIME incorrecto.
  • Sin Content-Security-Policy: sin restricción sobre qué scripts/recursos podían ejecutarse.
  • Sin Strict-Transport-Security: conexiones HTTP no forzadas a HTTPS.
  • Sin Referrer-Policy: URLs internas podían filtrarse a terceros.
  • Sin Permissions-Policy: cámara, micrófono y geolocalización sin restricción.

Corrección aplicada en next.config.mjs:

async headers() {
  return [{
    source: '/:path*',
    headers: [
      { key: 'X-Frame-Options',           value: 'DENY' },
      { key: 'X-Content-Type-Options',    value: 'nosniff' },
      { key: 'Referrer-Policy',           value: 'strict-origin-when-cross-origin' },
      { key: 'Permissions-Policy',        value: 'camera=(), microphone=(), geolocation=()' },
      { key: 'Strict-Transport-Security', value: 'max-age=31536000; includeSubDomains' },
      { key: 'Content-Security-Policy',   value: "default-src 'self'; script-src 'self' 'unsafe-inline' https://va.vercel-scripts.com; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' data: blob: https://images.unsplash.com; connect-src 'self' https://vitals.vercel-insights.com; media-src 'self'; frame-ancestors 'none'" },
    ],
  }]
}

Estado: CORREGIDA — 6 cabeceras de seguridad implementadas.

H-02 · A05:2025 — Security Misconfiguration · ALTA

Build con errores de TypeScript ignorados

Descripción: El archivo next.config.mjs contenía la configuración typescript: { ignoreBuildErrors: true }, lo que permitía que el proyecto compilara y desplegara a producción incluso con errores de tipos graves. Esta práctica elimina una capa esencial de verificación estática.

Impacto: Código con errores de tipo podía llegar a producción sin detección, generando comportamiento inesperado, crashes en runtime o acceso a propiedades indefinidas.

Corrección aplicada: Se eliminó la clave ignoreBuildErrors: true. Se resolvieron los 10 errores de TypeScript emergentes eliminando componentes shadcn/ui que referenciaban paquetes no instalados (ver H-10).

Estado: CORREGIDA — Build TypeScript estricto restaurado. tsc --noEmit pasa sin errores.

H-04 · A06:2025 — Vulnerable and Outdated Components · ALTA

Swiper 11.1.15 — Prototype Pollution

Descripción: La librería swiper@11.1.15 contenía la vulnerabilidad GHSA-hmx5-qpq5-p643 de prototype pollution. Un atacante podía manipular el prototipo de objetos JavaScript mediante propiedades especiales (__proto__, constructor), afectando el comportamiento global de la aplicación.

Corrección aplicada: Actualización a swiper@12.1.3. Se verificó compatibilidad previa: el componente client-photos-carousel.tsx usa únicamente Swiper, SwiperSlide y el módulo Autoplay, todos compatibles con la API de v12.

Estado: CORREGIDA

H-05 · A07:2025 — Identification and Authentication Failures · ALTA

Sin verificación de edad en sitio para adultos

Descripción: El sitio ofrece contenido exclusivo para adultos mayores de 18 años. Sin embargo, no existía ningún mecanismo de verificación de edad al ingresar, exponiendo el contenido a menores sin restricción alguna.

Impacto legal: En Chile, la exposición de contenido para adultos sin control de acceso puede acarrear responsabilidad legal según la Ley N° 20.120 y normativas del CNTV. Adicionalmente, representa una mala práctica frente al comité académico evaluador de la tesis.

Corrección aplicada: Se creó el componente components/age-gate.tsx implementado como wrapper global en app/layout.tsx:

  • Verificación en el lado del cliente con hidratación segura (evita mismatch SSR/CSR).
  • Cookie de sesión: luxx_age_verified=true; path=/; SameSite=Strict; Secure.
  • Dos acciones: confirmar mayoría de edad o salir del sitio (redirige a google.com).
  • Referencia visible a la política de privacidad (/privacidad).

Estado: CORREGIDA

H-06 · A09:2025 — Security Logging and Monitoring Failures · MEDIA

Sin registro de eventos de seguridad

Descripción: La aplicación carecía completamente de logging estructurado. No se registraban accesos, errores, eventos de autenticación ni intentos anómalos, lo que imposibilita la detección de ataques o la trazabilidad de incidentes.

Corrección aplicada: Se creó el módulo lib/logger.ts con las siguientes características:

  • Función logSecurityEvent() para eventos auditables (acceso al age gate, errores de ruta, etc.).
  • Función logError() para errores de aplicación.
  • Sanitización automática de datos sensibles: las claves password, token, apiKey, rut, cardNumber, cvv, bankAccount y similares son reemplazadas por [REDACTED] antes de cualquier log.
  • Estructura compatible con sistemas de monitoreo externos (formato JSON).

Estado: CORREGIDA

H-07 · A04:2025 — Insecure Design · MEDIA

UX engañosa en página de checkout

Descripción: La página app/checkout/page.tsx mostraba un badge de "Conexión cifrada" y un botón de pago habilitado, generando en el usuario la falsa impresión de que el sistema de pago estaba operativo y era seguro. En realidad, no existía ningún procesador de pagos integrado.

Impacto: Constituye una práctica de diseño engañoso (deceptive UX) que podría interpretarse como publicidad falsa o fraude al consumidor bajo la Ley N° 19.496 (Ley del Consumidor de Chile). También viola el principio de transparencia de la Ley N° 21.719.

Corrección aplicada:

  • Se agregó un banner visible de prototipo académico en la parte superior del checkout.
  • El botón de pago fue desactivado con disabled y aria-disabled="true".
  • El texto cambió a "Pago disponible próximamente" para comunicar honestamente el estado real del sistema.

Estado: CORREGIDA

H-08 · A05:2025 — Security Misconfiguration · MEDIA

Error boundary global inexistente

Descripción: La aplicación Next.js carecía de un componente global de manejo de errores (app/error.tsx). Ante un error no controlado en runtime, Next.js podía exponer stack traces completos al navegador del usuario, revelando rutas de archivos, estructura interna del código y versiones de dependencias.

Impacto: Exposición de información sensible de arquitectura (A05 — Information Exposure). Los stack traces son información valiosa para un atacante que busca vectores de explotación.

Corrección aplicada: Se creó app/error.tsx con las siguientes características:

  • Utiliza error.digest (hash opaco generado por Next.js) en lugar del mensaje de error real — nunca expone el stack trace al cliente.
  • Presenta una interfaz amigable con dos acciones: "Reintentar" y "Ir al inicio".
  • Compatible con el App Router de Next.js 16.

Estado: CORREGIDA

H-09 · Ley N° 21.719 — Cumplimiento Legal · CRÍTICA

Ausencia de páginas legales y enlaces rotos

Marco legal aplicable: Ley N° 21.719 de Chile — Protección de Datos Personales (vigente 2026). Obliga a todo responsable de datos a informar al titular sobre el tratamiento, finalidad, derechos ARCO+P y datos de contacto del responsable.

Descripción: El footer del sitio contenía enlaces a cuatro páginas legales ("Términos y Condiciones", "Política de Privacidad", "Política de Cookies", "Política de Eventos") que apuntaban todos a href="#" — es decir, no existían. Un usuario que intentara ejercer sus derechos ARCO+P (Acceso, Rectificación, Cancelación, Oposición + Portabilidad) no tenía ningún medio para hacerlo.

Impacto legal:

  • Infracción al Art. 14 quáter de la Ley 21.719: obligación de informar al titular antes de recopilar datos.
  • Infracción al Art. 40: sanciones de hasta 5.000 UTM para responsables que no provean mecanismos de ejercicio de derechos.
  • Incumplimiento de la obligación de transparencia activa.

Corrección aplicada:

  • Creación de app/privacidad/page.tsx — Política de Privacidad completa con base legal, finalidades, derechos ARCO+P, datos de contacto del responsable y plazo de respuesta (30 días hábiles).
  • Creación de app/terminos/page.tsx — Términos y Condiciones con descripción del servicio, limitaciones de responsabilidad y jurisdicción chilena.
  • Creación de app/cookies/page.tsx — Política de Cookies con tabla de cookies utilizadas, categorías y mecanismo de rechazo.
  • Creación de app/politica-eventos/page.tsx — Política de Conducta en Eventos con normas de comportamiento y procedimiento de reclamaciones.
  • Actualización del footer: los cuatro enlaces ahora apuntan a sus rutas reales.

Estado: CORREGIDA — 4 páginas legales creadas con contenido sustantivo.

4.2 Limitaciones conocidas

  • Rate limiting: No se implementó rate limiting en rutas de API (el proyecto no tiene rutas de API críticas en este estado). Se recomienda implementar al activar el sistema de reservas.
  • Age gate: La verificación de edad es por declaración del usuario (estándar de la industria para este tipo de sitios en Chile). No constituye verificación de identidad real.
  • CSP con unsafe-inline: La política CSP incluye unsafe-inline para estilos, requerido por Tailwind CSS 4. Para eliminarla se necesitaría migrar a CSS Modules o implementar nonces.
  • Sistema de reservas: Al activar el checkout con pagos reales, se deberá implementar: integración con procesador certificado PCI-DSS, validación server-side de inputs, y protección CSRF.
